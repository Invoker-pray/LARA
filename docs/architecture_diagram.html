Attention Accelerator Architecture — Track B

Target: Llama3-8B Attention Layer · bf16 Precision · Kria KV260 Platform (without AI Cores)

当前实现状态（2026-08-02）

当前 accepted 基线是 v2.5 P4 streaming/fused-PV：PL 时钟 83.333 MHz，Explore post-route WNS +0.021 ns、WHS +0.010 ns，资源为 165 DSP、95479 LUT、56940 FF、50 BRAM、48 URAM。设计是单序列 prefill，MAX_SEQ_LEN=512。宿主机完成 RMSNorm/QKV/RoPE，driver 在一次 start 后按 CSR_LOAD_REQ 服务 K/V/Q DMA；片上 K/V cache 每次保存一个 GQA group 的当前 KV head，不能描述为 8 个 KV head 同时全量驻留。accepted screening 当前只有 routed DCP，部署导出需运行 P4 export 脚本。

🎯 核心设计决策：为什么当前 KV head 需要驻留 URAM？

数据来源访问次数 (L=512, Tq=32, Tk=64)缓存策略
K 主机端 QKV 投影后传入 每个 Q tile 重用 — 当前 K head 为 128 KB；同一 group 的 4 个 Q heads 共享驻留数据 ✅ URAM group cache
每次缓存当前 GQA group 的 KV head，4 个 Q heads 复用一次 DMA
V 主机端 QKV 投影后传入 每个 Q tile 重用 — 当前 V head 为 128 KB；group 切换时由 driver 重载 ✅ URAM group cache
与 K 同步按 group 请求，避免重复传输
Q 主机端 QKV 投影后传入 1 次 — 外层循环按 tile 顺序遍历
总访存量: 512 × 128 × 2B = 128 KB		 ⚠️ 流式加载
每个 Q_tile 从 DDR 读一次就消费掉
仅需 2×Tq 的 Ping-Pong buffer
Wq/Wk/Wv/Wo 模型权重 0 次 — QKV 投影在主机端完成
权重不进入 FPGA Attention 路径		 ✅ 不在 FPGA 上
权重只用于 QKV 投影，与 Attention 计算分离

为什么权重不需要缓存在 FPGA？

QKV 投影的计算量是 Attention 的 ~1000×（Q 投影 537M MACs vs Attention 0.5M MACs/tile）。 QKV 投影计算和权重体量显著大于当前 Attention kernel。当前实现由 host_attention.py 完成投影/RoPE，再由 attn_driver.py 自动 DMA，FPGA 只做 Attention 计算。 这和赛题的 "attention mechanisms" 范围一致 — QKV 投影是前面的线性层，不属于 attention 机制本身。

类比 CIM 毕设

CIM 毕设中，权重 stationary — 权重预加载在 SRAM，输入流式广播。
Track B 中，K/V stationary — 每个 GQA group 的 K/V 请求后驻留在 URAM，Q 流式进入。
两者的共同原理：被反复读取的数据靠近计算单元，只读一次的数据流式进出。
不同的是"谁是被反复读取的数据" — CIM 中是权重（fc 每层权重），Attention 中是 K 和 V（FlashAttention 内层循环反复访问）。

关键数据流特征：

  • 当前 KV head 驻留 URAM — 每个 GQA group 加载一次，4 个 Q heads 和所有 KV tiles 复用；group 切换时重新加载
  • Q 流式消费 — 每个 Q_tile 从 DDR 加载后立即送入 MAC 阵列，消费后丢弃，仅需双缓冲
  • S_tile 和 P_tile 流式直通 — 从 MAC 阵列出来后直接流入 Softmax/下一级，不写回任何 SRAM（FlashAttention 核心）
  • QKV 投影在主机端完成 — 权重 (Wq/Wk/Wv/Wo) 不经过 FPGA，缩小了 FPGA 设计的范围和数据量

4. FlashAttention 双层循环 & K/V 访存模式

// ===== 对一个 GQA 组（4 Q heads + 1 KV head），head_dim=128 =====
// seq_len = L, TILE_Q = Tq, TILE_KV = Tk

// ★ 每个 GQA group 先由 core 发出 KV_LOAD_REQ
HOST_DMA K_group[g][0..L-1][0..127] // 当前 KV head，L×128×2 字节
HOST_DMA V_group[g][0..L-1][0..127] // 当前 KV head，L×128×2 字节
// driver 观察 CSR_LOAD_REQ，分别启动 K/V DMA；完成后该 group 驻留 URAM

// ★ 第二阶段：Attention 双层循环
for q_start = 0, Tq, 2×Tq, ..., L-1          // 外层: 遍历 Q 分块 — L/Tq 次迭代
    Q_tile = DDR_LOAD(Q[q_start : q_start+Tq])    // [Tq,128] bf16, 流式加载

    // 初始化 Online Softmax 状态
    m[0..Tq-1] = -inf;  l[0..Tq-1] = 0;  O_acc[0..Tq-1][0..127] = 0

    for kv_start = 0, Tk, 2×Tk, ..., L-1    // 内层: 遍历 KV 分块 — L/Tk 次迭代
        K_tile = URAM_READ(K_group[kv_start : kv_start+Tk])  // 当前 group
        V_tile = URAM_READ(V_group[kv_start : kv_start+Tk])  // 当前 group

        S_tile = Q_tile × K_tile^T                     // [Tq,Tk] fp32 — Phase A
        S_scaled = S_tile / √128 + causal_mask

        for i in 0..Tq-1:                               // Online Softmax 行并行
            m_new[i] = max(m[i], row_max(S_scaled[i,:]))
            correction[i] = exp(m[i] - m_new[i])
            P_row[i] = exp(S_scaled[i,:] - m_new[i])
            l[i] = l[i] × correction[i] + row_sum(P_row[i])
            O_acc[i,:] = O_acc[i,:] × correction[i] + P_row[i] × V_tile  // Phase B
            m[i] = m_new[i]

    // 归一化 + 写回
    for i in 0..Tq-1:
        O_tile[i,:] = bf16(O_acc[i,:] / l[i])
    DDR_WRITE(O_tile)

// ===== 访存量统计 (L=512, Tq=32, Tk=64) =====
// 当前 group 的 K/V DDR 读取: 2 × 512 × 128 × 2B = 256 KB
// 完整 8-group 事务共发送约 2 MB K/V；每个 group 的 K/V 在 4 个 Q heads 间复用
// Q/O 由各 Q head 的 tile 请求分批传输；实际时间以 DMA/compute counter 为准
// URAM 的作用是避免同一 Q head 的 KV tile 被重复从 DDR 读取

6. 设计方向推荐与不推荐

✅ 推荐采用

方向原理收益与 CIM 的关联
① K/V-Stationary 数据流 当前 K/V head 驻留 URAM，被每个 Q_tile 反复读取；GQA group 切换时由 driver 重载
类比 CIM 的 Weight-Stationary 思路		 消除同一 Q head 的 K/V DDR 重读；同组 4 个 Q heads 再共享一次 DMA 同为"反复读取的数据靠近计算单元"
② Q 流式加载 Q 只被遍历一次，每个 tile 从 DDR 加载后立即消费
仅需 2×Tq 的 Ping-Pong buffer		 省 512 KB URAM (vs 全量 Q Buffer) 类比 CIM 输入流式广播
③ MAC 阵列分时复用 同一 16×16 阵列做 Q×K^T (Phase A) + A×V (Phase B)
不承担 QKV 投影		 省 DSP (256 vs 两套阵列 512) 类比 CIM tile 分时做不同层的计算
④ 流式数据通路 S_tile → Scale → Softmax → P_tile → A×V 全程流水
中间结果不写回 SRAM (FlashAttention 自带)		 零 S/P 矩阵存储 (省 ~2 MB URAM) 类比 CIM 部分和流水累加
⑤ QKV 投影在主机端 QKV 投影计算量是 Attention 的 ~1000×
在 ARM 或预处理完成，FPGA 只做 Attention		 缩小 FPGA 设计范围，省 DSP + 省 BRAM 权重存储 软硬件分工 — 与 CIM im2col 软件预处理同理
⑥ 自适应循环次序 L≤512: Q-outer + 当前 GQA group KV cache
L>512: 尚未实现，列为 scalability 后续工作		 论文中可讨论的扩展性卖点 SPLIT_FACTOR 的双路径设计思路
⑦ 分块计算 (Tiling) FlashAttention 双层循环，这是整个设计的基础 使 Attention 计算能在有限的片上存储中完成 类比 CIM im2col 分块

❌ 不推荐采用

方向不推荐原因
⑧ 稀疏注意力 (Sparse Attention) 改变了 Llama3-8B 的计算输出，不符合 "aligned with Llama3-8B specification"。可在论文 Future Work 提及，不能作为主体方案。
⑨ 模型量化 (INT8/INT4) bf16 是赛题硬性要求。当前基线不做计算精度降级；任何压缩方案都必须单独进行精度评审。
⑩ QKV投影 + Attention 融合 Q 投影计算量 537M MACs vs Attention 0.5M MACs — 差了 1000×。融合会让 MAC 阵列 99.9% 时间在做投影，Attention 无资源可用。正确的做法是两者分离。
⑪ 大 MAC 阵列 (32×32+) 赛题要求 "as fewer as possible" DSP。大阵列增加 DSP 用量，且 DDR 带宽跟不上时 MAC 空转。应克制使用 DSP。
⑫ 权重常驻 FPGA Wq 32 MB >> BRAM 640 KB + URAM 2.6 MB，物理上装不下。且权重只用于 QKV 投影，投影在主机端即可。
