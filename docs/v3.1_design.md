# LARA v3.1 RTL/driver 设计：Q/K/V prefetch 与 ping-pong overlap

状态：设计阶段（未宣称支持，未生成 bitstream）  
日期：2026-09-20  
基线：`fa915c3 v3.0`

## 目标

v3.0 descriptor batching 已经降低了短序列的 DMA/request-service 固定开销，但
L512 的收益接近于零。v3.1 的主目标改为隐藏 `ST_LOAD_KV`、`ST_Q_INIT` 和
`ST_WRITE_O` 的 blocking stall，同时保持 v2.6 legacy 协议和 v3.0
descriptor/in-band fallback。

本阶段只冻结接口、状态和观测口径；在 VCS 和板测门禁通过之前，prefetch 开关
不得改变默认数据流，也不得把连续发送称为硬件 overlap。

## 当前 RTL 事实

- Q bank tag/ready 保护已落地（v3.1.0）：两 bank 各保存 group/head/tile
  tag，`q_load_done` 在 outstanding 与 ready 路径均要求 tag 匹配；
  `buffer_wait_cycles`（0x114）与 `kv_transport_stall_cycles`（0x110）
  观测计数器已可用。
- `hw/rtl/core/attn_core.sv` 已有 Q ping-pong bank，以及 next-Q-tile 的预取
  请求；`q_prefetch_next_head_or_group` 当前固定为 `0`（v2.6 起禁用；
  `tb_attn_top_loop_control(_delayed)` 的对应检查挂在 `+HEAD_GROUP_PREFETCH`）。
- `hw/rtl/axi/attn_axi_stream_sink.sv` 已支持 legacy、descriptor FIFO 和
  in-band segment framing；不能在未定义 ownership 的情况下让 DMA 覆盖正在计算
  的 cache。

## RTL 方案

### 1. 明确 buffer ownership（K/V 侧 v1 已实现，见 2026-09-23 v3.5.0）

v1 形态：单物理 bank + 四态协议（IDLE/FILLING/READY/ACTIVE）+ group tag；
早发请求在 bank 可重填（最后 head 最后 Q tile 排空）时才对 host 可见，
填充与最后 tile 的 normalize/writeback 重叠。物理双 bank 因 URAM 预算
（75% 已用）留待后续。协议教训见 `docs/design_pitfalls.md` §9。

为 Q tile 增加 `FREE/FILLING/READY/CONSUMING` 四态（两 bank 各一份），为 K/V
prefetch 增加 active/fill pair。每个 bank 必须同时保存：`group/head/tile` tag、
payload byte count、ready、error。计算端只能消费 `READY` 且 tag 完全匹配的 bank；
DMA 端只能写 `FREE` bank。

### 2. 解耦请求与计算

在 `attn_core` 保留现有 FSM 作为 compatibility scheduler，新增一个可关闭的
prefetch scheduler：

```text
compute_need -> request_issued -> fill_in_progress -> fill_ready
                                      \-> underflow/overflow
```

第一版只允许一个 outstanding K/V segment 和一个 outstanding Q segment；不做
continuous batching，不改变 BF16 arithmetic 或 tile 顺序。`ST_KV_READ` 只有在
active bank ready 时启动；若 fill 未完成，计数器将该等待记入新的 transport-stall
计数，而不是伪造 MAC-active 时间。

### 3. 新增 CSR 状态

```text
0x03C PREFETCH_CTRL   bit0 enable, bit1 clear/error, bit2 force legacy ownership   （未实现）
0x040 PREFETCH_STATUS bit0 supported, bit1 enabled, bit2 q_ready,                  （未实现）
                       bit3 kv_ready, bit4 underflow, bit5 overflow,
                       bits15:8 outstanding_count
0x110 PERF_TRANSPORT_STALLS  （已实现 v3.1.0+：kv_load_req_pending && !kv_load_done 周期）
0x114 PERF_BUFFER_WAIT       （已实现 v3.1.0：q_load_outstanding 等待周期，含与计算重叠部分）
```

旧 bitstream 对这些地址应返回 0；driver 必须先 capability-discover，发现不支持
时强制 `prefetch_mode=off`。0x110/0x114 为纯观测计数器，不改变任何数据流。

### 4. 安全顺序

先实现 Q next-tile 的 tag/ready 保护和计数，再实现 K/V 双缓冲；每次只打开一个
重叠方向。任何 underflow、overflow、tag mismatch、TLAST/segment mismatch 或
reset 中断都回退到 legacy scheduler，并置 sticky error。

## driver 方案

`sw/attn_driver.py` 已增加 `LARA_PREFETCH_MODE=off|descriptor|inband` 的配置
和 profile 字段，但当前是 metadata-only gate，不改变发送顺序。新增观测字段：

```text
prefetch_mode
buffer_wait_ms
input_dma_overlap_ms
transport_stall_ms
```

真正启用前必须增加：

1. capability read 与 CSR version/bit 定义；
2. descriptor tag 与 bank ownership 的 ACK；
3. timeout 后的 clear/retry/fallback；
4. profile 中分别记录 request-service、DMA transfer、buffer wait、transport
   stall，禁止用 `request_service_ms` 代替硬件 overlap。

## 分阶段验收

1. Python 单测：配置解析、默认 off、非法值拒绝、旧 MockMMIO 行为不变。
2. VCS：legacy/descriptor/in-band bit-exact；Q bank alternation；backpressure；
   underflow/overflow；reset/clear；counter retention。
3. Vivado：timing、LUT/FF/BRAM/URAM、sink/FIFO/mux critical path 和 DRC。
4. KV260 A/B：v3.0 legacy、v3.0 descriptor、v3.1 prefetch off、v3.1 prefetch
   on；比较 `pl_stall_ms`、`pl_core_active_ms`、PL transaction、host E2E、DMA
   transfers 和 bit-exact output。

只有第 1--3 阶段通过，且第 4 阶段的 prefetch-on 仍 bit-exact，才允许把
`LARA_PREFETCH_MODE=descriptor|inband` 从 metadata-only 改成实际硬件路径。
